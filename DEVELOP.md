## Introduction

Notes for developers to test and extend BIDSvue.

## Build a release

`bun tauri build` produces an unsigned bundle for the host platform. `bun run release:macos` codesigns, notarizes, and staples a macOS arm64 DMG (needs `APPLE_ID_APP` + a local `notarytool` keychain profile). The release script automatically sources `.env.macos-release` when present; that file is gitignored and is the local place for Apple credentials or release overrides (`BIDSVUE_MACOS_RELEASE_ENV=/path/to/file` can point elsewhere). GitHub Actions builds unsigned Linux x86_64 and Windows x86_64 bundles via `.github/workflows/crossplatform-bundles.yml`; use manual dispatch when downloadable artifacts are needed, then smoke-test them before publishing. `dcm2bids` and `heudiconv` are PATH-resolved (user installs via `pip`). The bundled `niimath` is a **BSD-2** build on every platform (the GPL `spm_coreg` path was removed) — see [NOTICE.md](NOTICE.md).

## Quick start for beta testers

The app's main flows in order of how a fresh install can exercise them. File issues at <https://github.com/niivue/BIDSvue/issues>; the "action failed" chip in the status bar copies the error + a full diagnostic report so you can paste a self-contained bug report.

1. **Open an existing dataset.** Drag a BIDS root onto the launch screen or click **Open existing BIDS dataset…**. The status bar shows a live scan count; the validator runs automatically when the scan completes. The View menu's **Show hidden** toggle reveals `sourcedata/` / `derivatives/` / dotfiles dimmed. The validator also warns on potential identity leaks — date-like `sub-`/`ses-` entity labels and real (year > 1925) `acq_time` values in `*_scans.tsv`.
2. **Rename a BIDS entity.** Right-click a `sub-XX` folder → **Rename entity…** to test the cross-reference rewriter (cascades to `participants.tsv`, `*_scans.tsv`, `IntendedFor` in fmap sidecars). Use the History panel to undo. Every mutation is reversible. **Minimize a dataset** (Edit → **Minimize dataset…**) removes redundant optional entities — collapsing a single-session layout (`sub-X/ses-Y/…` → `sub-X/…`) or dropping a `run-1` present on every scan — refusing anything that would invalidate BIDS or collide; also reversible from History.
3. **Fetch a DataLad pointer.** Open a DataLad-managed dataset (e.g. any [OpenNeuro](https://openneuro.org) dataset cloned via **Clone DataLad dataset…**). Pasting an `openneuro.org/datasets/<id>` page URL is auto-rewritten to its git-cloneable GitHub mirror (with a hint shown), so the web page address works directly. Pointer files show a cloud chip in the tree view; click the Fetch chip in Preview to pull bytes from S3 / `web` remotes. Cancel chip is in the status bar.
4. **Deface an anatomical scan.** Select a `_T1w.nii.gz` → toolbar **Deface…**. Offers a choice between the CPU sidecar defacer `allineate` (12-DOF affine, the niimath `-deface` path, on every bundled platform) and the WebGPU `mindgrab` family (`mindgrab`, `mindgrab8`, and `mindgrab8robust`, which crops the neck via a niimath `-robustfov` port before the model runs). Sidecar defacing and mindgrab mask dilation run through the bundled native `niimath` binary (there is no WASM niimath). The pristine bytes are mirrored under `<dataset>/sourcedata/` for revert.
5. **Cloud share.** Toolbar **Share…** opens the three backend tiles (OpenNeuro, brainlife, EBRAINS). Auth is paste-in JWT from each provider's web UI; the panel walks file selection, hashing, and upload. An interrupted upload surfaces a recovery banner on next open of the dataset.

**AI assistant (alpha).** The integration is **built into every release and enabled by default** - stock DMG builds ship the AI tile. To disable it, build with both off-switches set in lockstep: `VITE_BIDSVUE_ENABLE_AI=0` (renderer - dead-codes the AI UI) AND `BIDSVUE_DISABLE_AI=1` (Rust - short-circuits the AI command surface so a compromised renderer cannot drive it in a disabled build). Recipes: `bun run dev:no-ai` for a dev session without AI, `BIDSVUE_DISABLE_AI=1 bun run release:macos` for a no-AI DMG (the release script sets both env vars). When a dataset is open, BIDSvue spawns the selected CLI (Claude Code, Codex, or Gemini - M-AI4.5b: Gemini dataset sessions run under a Policy Engine default-deny that blocks its built-in file/shell tools, so only BIDSvue MCP tools reach the dataset) with a `--mcp-server` attached and the AI can call `read_file` / `list_files` / `get_dataset_summary` / `run_validator` / `get_validator_issues` against the dataset without per-call permission prompts. **Note on Codex:** dataset-bound Codex requires `--dangerously-bypass-approvals-and-sandbox`, so prefer Claude for confined dataset work. Write tools (`rename_entity` / `save_text_file` / `save_sidecar` / `delete_file`) route through the approval-gate control bridge and block on an Approve/Reject chip before any mutation runs. Conversation history is capped at 5 turns / 32 KiB. **Privacy:** enabling AI means dataset contents the tools read leave your machine; CLI-spawn mode sends via the selected vendor CLI, and direct OpenAI-compatible mode sends via BIDSvue to the configured endpoint. **AI now runs on Windows (experimental)** with a per-user-SID named-pipe bridge, pipe-owner verification, fail-closed ACLs, direct `.cmd`/`.bat` shim launch, absolute PowerShell/taskkill launches, telemetry retries, and Job Object descendant cleanup; it still needs a clean-VM end-to-end Windows CLI smoke before being called shipped. See ROADMAP "AI integration follow-ups" and [LIMITATIONS.md](LIMITATIONS.md) for per-runtime egress detail.

When something doesn't work the way you expect, the **action failed** chip in the status bar copies error + diagnostic report to your clipboard — that's the fastest path to a useful bug report.
