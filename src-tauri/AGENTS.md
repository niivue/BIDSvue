# src-tauri/ — Rust / backend gotchas

Loads when working under `src-tauri/`. Root invariants live in [../AGENTS.md](../AGENTS.md); this file is the backend-only detail. Deep design rationale: [../ARCHITECTURE.md](../ARCHITECTURE.md) §3 (Rust surface) + §6 (security boundary).

## Security boundary (the whole point of the Rust surface)

The Rust surface is intentionally narrow — security boundary work, no business logic. Renderer names a `(toolId, argv)` or a path + token; Rust selects the fixed binary and re-validates the **complete argv shape** + path before acting. TS-side validators are first-line UX only; Rust is authoritative.

- **Capability is narrow at startup** ([capabilities/default.json](capabilities/default.json)): `fs:scope` = `$APPDATA/**` + `$APPCACHE/**` + `$RESOURCE/**`, `$APPDATA/trust/**` denied. fs permissions declared in **string form** (no per-permission `allow` arrays — Tauri 2 enforces per-permission `allow` BEFORE the runtime scope check). Pre-escaped globs mean `<root>/**` does NOT match dotfiles → atomic-write temp name is `<basename>.bidsvue-tmp-<opId>` (no leading dot); editable dotfiles (`.bidsignore` etc.) need a per-file carve-out in `apply_widen_dataset` AND fall back to `read_authorized_text_file` for reads.
- **Runtime widening is token-gated.** `pick_dataset_directory`/`pick_file` mint an in-memory token (5-min TTL, descendant-aware); `mint_token` does NOT persist. `allow_dataset_scope(root, token)` widens fs+asset (viewer paths); `allow_fs_scope(path, token)` widens fs only (import sources). Trust-set members widen via `widen_to_trusted_path` (no token). Renderer calls `trust_path(target, token)` explicitly AFTER the op succeeds. Scope API is append-only (only restart drops a scope). `..`/`.` rejected at the trust boundary.
- **`validate_authorized_path_canonical`** (lexical check THEN `std::fs::canonicalize` through every symlink, re-checked against trust) MUST back any Rust command that follows symlinks on `read`/`write`/`metadata`. The lexical-trust-then-canonical-containment split is the rule: trust membership stays LEXICAL on the as-typed `dataset_root` (so symlinked picker roots match — NEVER canonicalize `dataset_root` into `is_under_any_runtime_path`), then canonicalize root+input+output before containment re-check + a pre-existing-output refusal. `resolve_deface_spawn` / `resolve_niimath_dilate_spawn` / `openneuro_upload_file` are the canonical callers; any new follow-the-path command MUST reuse it.
- **`run_ai_prompt` dataset root** must canonicalize THEN require EXACT membership in `TrustStore::is_runtime_dataset_root_member` (not `is_under_any_runtime_path` — a child of a trusted root is NOT a valid AI root). Bare-chat (empty string) is the only bypass. AI session IDs validated as v4 UUIDs.

## Process boundary ([process.rs](src/process.rs))

- No `shell:allow-execute` (plugin-shell uninstalled). `run_import_process` / `probe_import_tool` / `run_deface_process` / `run_bids_validator` are the spawn points; each re-validates argv + paths before spawning. `dcm2bids` spawns with `PATH=<bundled sidecar dir>:<inherited PATH>` so its `shutil.which('dcm2niix')` finds the bundled sibling.
- **dcm2niix `-ba` semantics:** `-ba y` strips PII *and* dates; `-ba n` keeps everything (leaks PII — do NOT revive without an explicit decision); `-ba o` (v1.0.20260520+) strips PII but keeps `AcquisitionDateTime`. `buildReproinArgv` emits `-ba y` for anonymize=true, `-ba o` for false. `validate_dcm2niix_argv` accepts `y`/`n`/`o`/`i`.
- **Clone-URL validation moved to the `datalad-rs` crate** (`datalad_rs::url::validate_clone_url`); `validate_abs_path` stays in `process.rs`. SSH/SCP validators in the crate's `ssh` module. Startup scrubs `GIT_SSH*`/`GIT_PROXY_COMMAND` + sets `GIT_TERMINAL_PROMPT=0`/`GIT_ASKPASS=/usr/bin/false`/`SSH_ASKPASS_REQUIRE=never` BEFORE the WebView (gix SSH inherits these); `SSH_AUTH_SOCK` NOT scrubbed. **`DISPLAY=""` is set on macOS/Windows but NOT Linux** (`#[cfg(not(target_os = "linux"))]` in `git_safety_env_set_for_startup`): the Linux GTK WebView reads `DISPLAY` at `gtk_init()`, so blanking it process-wide makes the window fail to initialize ("Failed to initialize GTK"). The X11-askpass threat stays covered on Linux by `SSH_ASKPASS=/usr/bin/false` + `SSH_ASKPASS_REQUIRE=never` (process-wide) plus the per-spawn `process::git_safety_env_pairs` scrub, which still blanks `DISPLAY` for git/ssh CHILD processes on every platform. Do NOT re-add an unconditional `DISPLAY=""` — it breaks the Linux build (fixed 2026-06-30; `startup_env_set_blocks_x11_askpass_fallback` test is cfg-split to pin this).

## When (and only when) to add Rust

Rust enters only when measurement proves TS is the bottleneck for a specific op. Two pre-identified triggers, **neither fired**: scanner port (M1 measured 1.42 s for 100k files; gate at `bench/baselines/scanner.json`) and backup/undo atomicity (M6 shipped pure-TS LIFO rollback). When you do add Rust: narrow surface, generate TS bindings via `tauri-specta`, **keep the TS fallback** so the cloud port still works. Reaching for Rust outside these triggers → stop and write down the measurement.

## Durable / log / fs escape-hatch commands

- `append_log_line(path, line)` — `O_APPEND`+`sync_all`, validates target is exactly an `operations.log` under `<appDataDir>/datasets/<safeKey>/`; rejects multiline/`\r`. (plugin-fs `writeTextFile` truncates → torn-write zeroes the log.)
- `read_authorized_text_file` / `purge_legacy_bidsvue_dir` — bypass plugin-fs's broken-for-dotfiles glob matcher; both runtime-authorized-path gated.
- `read_only_batch` (one per `readDir` → tree lock chips + Save gate) / `chmod_path` (preserve mode across atomic write; Windows no-op).
- `read_link` / `stat_followed` / `detect_pointers_batch` — DataLad pointer detection. **`stat_followed` bypasses plugin-fs's broken-for-symlinks scope check** (Tauri's `Scope::is_allowed` mis-resolves relative annex targets) — use it for fetched-state detection.

## DataLad native ([datalad_native/](src/datalad_native/))

The engine is the vendored **`datalad-rs` submodule** at `crates/datalad-rs` (path dep, workspace member; `git submodule update --init --recursive` after clone). `datalad_native/commands.rs` (+ thin `mod.rs`) is the BIDSvue boundary ONLY: trust/path validation, cancellation bridging (`CancellationRegistry` → engine `AtomicBool`/`Notify`), `Channel<DataladStreamLine>` progress, operation-log/undo integration. `datalad_native_version()` reports the crate's identity (`datalad_rs::{VERSION,GIX_VERSION,DATALAD_COMPAT_VERSION}`), pinned by `backend_info_uses_crate_constants`. Native `backend: {name, version}` MUST thread into every commit's `operations.log` details + the pending-record refresh after the call. `CancellationScope` ([runtime.rs](src/runtime.rs)) is the canonical shape for any new cancellation-aware command (Drop always signals + deregisters). Push to upstream is out of scope (Save → Cloud Share).

## Sidecars + recompile recipes

Source-of-truth binaries: `resources/<platform>/<basename>` (committed); Tauri reads `binaries/<basename>-<triple>` (gitignored, staged by `scripts/stage-sidecars.ts` from `postinstall`). `stage-sidecars.ts` owns the Windows `<name>-x86_64-pc-windows-msvc.exe` naming rule. Fresh clone: `git clone --recurse-submodules` (the `datalad-rs` engine is a submodule — or run `git submodule update --init --recursive` after a plain clone), then `bun install && bun tauri dev` Just Works on macOS arm64 / Linux x86_64 / Windows x86_64. Swapping a bundled binary → `git add` the new `resources/` file + update CI `sidecar_basenames` + `macos-release.sh`.

- **dcm2niix (macOS):** build upstream via CMake with `-DUSE_OPENJPEG=ON` (the root Makefile path silently drops JP2), then `cp build/bin/dcm2niix resources/darwin/ && bun run scripts/stage-sidecars.ts`. `-v | head -1` MUST show BOTH `(JP2:OpenJPEG)` AND `(JP-LS:CharLS)`.
- **niimath (macOS):** CMake SuperBuild with **static zlib-ng** and no OpenMP/zstd/GPL (2026-07-12, v1.0.20260712+, the "modern-allineate" niimath): `cmake -S <niimath> -B <build> -DZLIB_IMPLEMENTATION=zlib-ng -DUSE_OPENMP=OFF -DENABLE_ZSTD=OFF -DENABLE_GPL=OFF -DCMAKE_BUILD_TYPE=Release && cmake --build <build> -j`, then `cp <build>/bin/niimath resources/darwin/niimath && bun run scripts/stage-sidecars.ts`. **`-DUSE_OPENMP=OFF`** is load-bearing for the notarized bundle (the default links Homebrew `libomp` signed under a different team ID → dyld refuses it); zlib-ng is compiled **statically** (SuperBuild builds ZLIB_COMPAT itself), and `-DENABLE_ZSTD=OFF` avoids the Homebrew `libzstd` landmine. **Verify `otool -L` lists ONLY `/usr/lib/libSystem.B.dylib`** (zlib-ng is static, so — unlike the old `-lz` build — there's no `libz.1.dylib`); any `/opt/homebrew/...` is a team-ID landmine. **Do NOT enable GPL** — `-spm_coreg`/`-spm_deface` stay out so the binary is **BSD-2**; confirm `niimath -h` has NO `-spm_deface`. These flags are macOS-only. (The bundle re-signs the sidecar during `release:macos`.)
- Linux/Windows sidecars are pinned AppVeyor artifacts (`bun run fetch-sidecars` + the sha256 map), also BSD builds. niimath is BSD on every platform; the deface paths are the three `allineate*` variants (all `-deface`, differing by fixed `-robustfov`/`-cost hel` flags — see `deface_variant` in [process.rs](src/process.rs)) + the mindgrab `niimath_dilate` mask dilation. All platforms use the 2026-07-12 modern-allineate engine contract: default `-deface` is FAST and explicit `-cost hel` selects the AFNI-style Hellinger engine. Linux/Windows pin the successful PR #66 merge build `12-Jul-2026_g74e9bbc`; keep those job IDs and extracted-binary SHA-256 values synchronized with the committed resources.
- **niimath bundled binary is the ONLY niimath** (WASM dep removed). The mindgrab 8 mm dilation runs through the `niimath_dilate` tool: `resolve_niimath_dilate_spawn` builds the spawned argv from the CANONICAL input/output/threshold (zero raw renderer bytes reach the child) + refuses pre-existing output. Same lexical-trust-then-canonical rule as deface.

## Validator

`bids-validator-rs` is the default backend, a bundled sidecar (macOS arm64 / Linux x86_64 / Windows x86_64), spawned by `run_bids_validator` with fixed argv (`--format json --content-mode parity --link-mode no-follow`). Build-time switch `VITE_BIDSVUE_VALIDATOR_BACKEND` — unset/`rust` = sidecar; `js` = in-WebView `@bids/validator` 2.4.1. The dispatcher dead-codes the unused branch so rust-mode doesn't carry the ~9 MB JS chunk. (Validator RUNS in the WebView for the JS backend — see [../src/AGENTS.md](../src/AGENTS.md) / ARCHITECTURE for that path.)

## AI Rust surface ([ai/](src/ai/))

- **Default-ON, compiled into every build** (no Cargo `ai` feature - `tauri dev` hardcodes `--no-default-features`). Off-switch needs BOTH gates: `VITE_BIDSVUE_ENABLE_AI=0` (renderer dead-code) AND `BIDSVUE_DISABLE_AI=1` (`ai::ai_disabled_at_build()` refuses `run_ai_prompt`/`probe_ai_clis`/`--mcp-server`). No-AI DMG: `BIDSVUE_DISABLE_AI=1 bun run release:macos`. **The control bridge is cross-platform**: a Unix-domain socket on Unix (`SO_PEERCRED` peer-uid check) and a **named pipe on Windows** (`ai::bridge::serve_control_pipe`) secured by a per-user-SID DACL via `ai::win`; both drive the SAME transport-generic `handle_conn` (bearer + constant-time compare + generation checks). Windows CLI support includes PATH backfill for `~\.local\bin` / `%APPDATA%\npm`, direct `.cmd`/`.bat` shim launch (no hand-wrapped `cmd /C`; BatBadBut regression pinned), absolute `%SystemRoot%\System32` launches for PowerShell `.ps1` shims and `taskkill.exe`, fail-closed ACL hardening for session dirs/files/workdirs, fail-fast secure first named-pipe creation, pipe-owner-SID verification before sending the bearer, 20s/130s client read timeouts, telemetry retry-until-success semantics, and a `KILL_ON_JOB_CLOSE` Job Object assigned to the AI child so its descendants are reaped on cancel (explicit `TerminateJobObject`) and on normal exit (job handle closes when `job_guard` drops) — see the assign-race residual under "Documented residuals" below. Tests cover the batch-shim injection case, PATHEXT filtering, the real Windows named-pipe relay, the Windows control-pipe client, the pipe-open retry predicate, the no-clobber credential write, the request-line timeout, and the fail-closed launch. **Audit 2026-07-03 round 5 refinements:** Unix now ALSO reaps its process group on the normal-exit arm (`kill_ai_process_group` under `#[cfg(unix)]`), symmetric with the Job Object — do NOT drop it thinking it's Windows-only; the pipe SDDL sets an explicit `O:{sid}` owner (without it an ELEVATED/Administrators token defaults the owner to S-1-5-32-544 and `verify_current_user_owner_handle` would reject every connection — breaking the bridge under elevation); `handle_conn` has a `REQUEST_LINE_DEADLINE` (30s) after the bearer so an authenticated-then-stalled peer can't pin a task; Windows `which_with_path` miss now FAILS CLOSED (no bare-`argv[0]` fallback); Windows `write_file_0o600` uses `create_new`+`sync`+fail-closed DACL (no-clobber parity). **Audit 2026-07-03 round 6 — the five previously-deferred items are now ALL FIXED (with tests):** (a) `enforce_canonical_scope` takes `allow_annex`; content-writes (`save_text_file`/`save_sidecar`) may NOT resolve into `.git/annex`, while reads and `delete_file` still may (a delete only removes the working-tree symlink); (b) the shared SDDL ACE is now `OICI`-inheritable so session-dir children inherit the user-only ACE at creation, closing the credential-file window; (c) `validate_control_bridge_request` rejects a non-string `path`; (d) shared `pipe_open_retryable` predicate + `PIPE_OPEN_ATTEMPTS`/`PIPE_OPEN_RETRY` consts across both Windows pipe-open loops; (e) both `serve_control_socket` and `serve_control_pipe` spawn handlers into a `JoinSet` (reaped each iteration) so relay teardown aborts in-flight `handle_conn` tasks. **Documented residuals (low-severity, ACCEPTED — see [LIMITATIONS.md](../LIMITATIONS.md)):** (1) **Job-Object assign race** — the child is spawned running (tokio has no `CREATE_SUSPENDED`), so a grandchild spawned in the microsecond window before `AssignProcessToJobObject` is not a job member and can escape reaping on Windows normal exit; the practical window is tiny (cmd.exe hasn't started node yet) and a leaked orphan hits a dead pipe. The race-free fix (raw `CreateProcess` + `CREATE_SUSPENDED` + `ResumeThread`) is disproportionate — do NOT bolt `taskkill /T` onto the normal-exit arm (the pid may be reused). (2) **`serve_control_pipe` PERSISTENT re-create failure** — transient connect/re-create failures now self-heal via bounded backoff (`MAX_PIPE_FAILURES`=10 x `PIPE_RETRY_BACKOFF`=50ms; the failure counter resets after every clean accept, so a long healthy session can't drift to the cap), and only 10 CONSECUTIVE failures make the relay give up accepting new clients (it still serves the in-flight one, detached, and logs clearly), after which bridge reads + writes degrade for the rest of the session (in-process `read_file`/`list_files` still work) until the user restarts the session — bounded, no security impact. **Audit 2026-07-03 round 7 — FIXED (with tests):** cross-platform post-open fd TOCTOU verification — `verify_open_fd_in_scope` is now real on macOS (`F_GETPATH`), Linux (`readlink /proc/self/fd/<n>`), and Windows (`ai::win::final_path_for_handle` → `GetFinalPathNameByHandle`), feeding a shared `check_real_path_in_scope`, not a macOS-only no-op; required write-argument enforcement in `validate_control_bridge_request` (each write tool's required keys must be present + correctly typed BEFORE relay — `save_sidecar.json` allows string OR object); `serve_control_pipe` bounded-backoff connect/re-create recovery (residual 2 above); and `#[cfg(unix)]`-gating for the four Windows-unused test imports in `lib.rs`. The per-call Windows `block_on` runtime is DELIBERATE (concurrent `std::thread` dispatch — a shared current-thread runtime can't be driven from multiple threads), documented at the call site. **Audit 2026-07-04 round 8 — FIXED:** the Windows Job-Object SETUP-failure paths in `run_ai_prompt` ([ai/spawn.rs](src/ai/spawn.rs)) leaked the already-spawned child — a `?`/`map_err(...)?` on `child.raw_handle()` (None) and `KillOnCloseJob::new()` (Err) returned AFTER `command.spawn()` without killing/reaping (a tokio `Child` is NOT kill-on-drop), so on those unlikely error arms the CLI kept running. All three post-spawn arms (raw-handle None, job-create fail, assign fail) now do `kill_ai_process_group(child_pid)` + `child.start_kill()` + a timed `child.wait()`, matching the stdout/stderr-`None` cleanup idiom; the only statement between a successful spawn and a live `job_guard` is `child.id()`, so no early return skips cleanup. This is the SETUP-failure leak — distinct from the ACCEPTED assign-*race* residual (1) below, which is about a grandchild spawned in the pre-assign microsecond window. **Windows AI status: RELEASE-CANDIDATE — every known code/security concern through round 7 is closed and machine-verified (`cargo test ai::` green + `cargo test --workspace` green on Windows). The SINGLE remaining gate before dropping the "experimental" label is a manual clean-VM three-CLI (Claude/Codex/Gemini) full-session smoke with a real approved write** (no unit test substitutes for it). The wider `cargo test --workspace` Windows gate passes too: the `process`/`trust` POSIX-path fixtures route through the `testpath::abs` helper. Do NOT re-add a `cfg(unix)` gate on `run_ai_prompt`.
- **`BIDSVUE_MCP_TOOL_ALLOWLIST`** ([ai/spawn.rs](src/ai/spawn.rs)) is the single source of MCP read-tool pre-approval; **wildcards forbidden** (would auto-approve future write tools, bypassing the bridge). Bidirectional parity tests pin allowlist ↔ `mcp/tools.rs`. Write tools route through the M-AI5 approval-bridge UI, never CLI pre-approval.
- Claude variadic flags (`--tools`/`--allowedTools`) MUST be terminated with `--` before the prompt. MCP-wired (dataset) Codex uses `--dangerously-bypass-approvals-and-sandbox` — Codex's sandbox CANCELS every MCP tool call, so the bypass is the ONLY config that runs them (user-approved tradeoff, see LIMITATIONS.md); bare-chat Codex (no MCP) keeps `--sandbox read-only`. The dataset path carries NO `-c approval_policy` and NOT the top-level `--ask-for-approval` flag — regression tests assert both are absent (and that `--sandbox` is gone on the MCP path). All pinned by regression tests.
- Spawn lifecycle: `stdin Stdio::null` + separate-task drain + wait-after-kill; cancellation registers at function entry BEFORE validation/spawn (sticky `PreCancelled` + `select! biased`); early returns deregister + remove the session dir via the `DeregisterGuard` RAII. Path authorization Rust-authoritative at the chokepoint: `.git*`/`.datalad`/`.bidsvue`/`.heudiconv`/`.hg`/`.svn` blocked for read+write; backslashes rejected; top-level `derivatives`/`sourcedata`/`code` refused via `validate_ai_rel_path`.

## CI / release

`bun run check` = the full pre-push gauntlet (validator-artifacts, lint, typecheck, i18n, bun tests, build, `cargo fmt --check`, `cargo test --workspace`). `cargo test`/`cargo check` use `--workspace` (covers the datalad-rs crate). **`bun run check` now passes end-to-end on Windows (2026-07-03) — both the Rust `--workspace` gate and the frontend bun suite are path-portable.** The `process` / `trust` Rust suites previously reported ~34 failures on Windows from tests that assert POSIX absolute-path shapes (`/tmp/...`, `/Users/...`, `/ds/...`); those fixtures now route through the `testpath::abs`/`absp` helper ([src/testpath.rs](src/testpath.rs)), which drive-letter-prefixes a POSIX spec on Windows and leaves it unchanged on Unix, so `cargo test --workspace` passes on all three platforms. The frontend twin is `toPosix` ([../src/lib/test-utils/posix.ts](../src/lib/test-utils/posix.ts)) — the `*.test.ts` files that build expected paths via Node's `path.join` (native backslashes on Windows) normalize both sides through it before comparing, so the bun suite passes on Windows too. Line endings are LF repo-wide via `.gitattributes` (`* text=auto eol=lf`, plus explicit `binary` on known assets; keep `core.autocrlf` false locally) — otherwise Windows checkouts get CRLF and the LF-only Biome formatter flags every file, making `bun run check` report hundreds of spurious line-ending errors. CI checkouts pass `submodules: recursive`; `macos-release.sh` preflights the submodule. macOS arm64 build pinned to `macos-14` (arm64 preflight). Notarized release is local (`bun run release:macos`) — asserts clean tree, version sync (package.json / tauri.conf.json / Cargo.toml), staged sidecars, no `file:`/`link:` dep specs.
